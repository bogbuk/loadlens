# Дизайн: «Авто-пилот» таба DAT (авто-рефреш + удержание сортировки)

Date: 2026-06-22
Status: approved

## Суть

Отдельный таб с выдачей DAT работает в фоне: по таймеру (60–120 с + джиттер) кликает
родную кнопку **Search/Refresh** DAT, и после прихода свежих результатов **повторно
применяет выбранную сортировку** через родной сорт-дропдаун DAT (рефреш её обычно
сбрасывает). Диспетчер работает в другом табе — фоновый таб не дёргает.

«Поле сортировки + ASC/DESC» и «авто-обновление» — две части одного режима: сортировка у
DAT уже есть вручную, ценность — *удерживать* её после каждого авто-рефреша.

## Решения (из брейнсторма)

- Сортировка строк DAT — через **родной сорт-дропдаун DAT** (rate/age), не своя перестановка DOM.
- Авто-рефреш — **клик по родной кнопке Search/Refresh** DAT (не reload), интервал **60–120 с + джиттер**.
- Фича **по умолчанию ВЫКЛючена**, явный opt-in.

## Компоненты

### `extension/adapters/dat.adapter.js`
- `REFRESH_SELECTORS`, `SORT_SELECTORS` — **заглушки** (как остальные DOM-селекторы DAT, кроме
  row-якоря). Заполнить с живой сессии позже.
- `clickRefresh()` — найти и кликнуть кнопку Search; вернуть `true/false` (нашлась ли).
- `applySort(key)` — открыть mat-select сортировки, выбрать опцию по тексту/значению; `true/false`.
- `readSortOptions()` — распарсить живой дропдаун → `[{key,label}]`, чтобы наш контрол не хардкодил
  список опций DAT. Если дропдаун не найден → пустой массив (контрол показывает фолбэк-набор).

### `extension/content.js`
- Таймер авто-рефреша: читает `ll_autorefresh` из storage; `setInterval` с джиттером. В фоновом
  табе Chrome троттлит таймеры до ≥1 мин — совпадает с нашим интервалом.
- После обновления `gqlLoads` (перехват уже детектит приход данных) → `adapter.applySort(ll_sort)`.
- Контрол в шапке панели: тумблер «Авто-рефреш» + дропдаун сортировки + ASC/DESC.
- Чистая функция `nextDelay(base, jitter)` — расчёт следующего интервала (тестируемая без таймеров).

### `extension/popup.*`
- Секция «Авто-пилот»: вкл/выкл, интервал (дефолт 90 с), выбранная сортировка.
- Пишет в `chrome.storage.local`: `ll_autorefresh = {on, intervalMs}`, `ll_sort = {field, dir}`.

## Поток данных

```
popup/панель → chrome.storage (ll_autorefresh, ll_sort)
            → content.js (DAT-таб): таймер → adapter.clickRefresh()
            → DAT шлёт FindLoads → inject.js перехватывает → gqlLoads обновляется
            → adapter.applySort(ll_sort) → render()
```

## ToS-граница (осознанный сдвиг)

Текущая строчка CLAUDE.md: «мы НЕ инициируем запросов к DAT — inject.js только наблюдает».
Авто-клик Search формально заставляет приложение DAT слать FindLoads. Поэтому:
- по умолчанию ВЫКЛ, явный opt-in;
- интервал 60–120 с **с джиттером** (имитация человека), не чаще; soft-cap на клики;
- нарратив: «автоматизируем клик, который диспетчер и так делает руками, в его же сессии»;
- зафиксировать сдвиг в ToS-секции CLAUDE.md явно.

Это НЕ путь Convoy: мы не вызываем GraphQL/REST DAT напрямую с токеном — мы кликаем их же
UI-кнопку как пользователь.

## Тесты

- `dat.adapter`: юнит на `applySort`/`clickRefresh`/`readSortOptions` против HTML-фикстуры (строки/jsdom-lite).
- `content`: чистая `nextDelay` — границы джиттера [base, base+jitter].

## Блокер

`REFRESH_SELECTORS`/`SORT_SELECTORS` — заглушки. Для заполнения нужен HTML с живой сессии DAT:
кнопка Search/Refresh + сорт-дропдаун (mat-select с опциями вроде «Rate - Highest»).
До этого фича собирается и тестируется на фикстуре, на живой странице селекторы уточняются.
