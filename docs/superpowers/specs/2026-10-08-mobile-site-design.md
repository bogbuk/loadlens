# Сайт под телефон: лендинг, HOS-калькулятор, установка через бота

Дата: 2026-10-08. Статус: дизайн согласован в чате, ждёт ревью спеки.

## Зачем

Трафик из Reddit (и будущий TikTok) приходит с телефона. На телефоне сайт вёрстку не ломает, но:

- главная кнопка «Add to Chrome, free» (5 мест на лендинге + блок под калькулятором) — тупик: расширение
  с телефона не поставить;
- баннер cookies закрывает ~треть первого экрана;
- в калькуляторе результат «Time left» лежит под формой высотой 2–3 экрана — ввод не даёт видимой реакции.

**Цель мобильного посетителя (решение 3 = «оба сценария»):**
- на калькуляторе — пользоваться и возвращаться (результат на виду, запоминание, офлайн, иконка на экране);
- на лендинге — переслать себе ссылку на установку на компьютер.

**Успех:** в Метрике у мобильных визитов появляются цели `share_link` / `tg_install` / `a2hs`; в калькуляторе
нет мобильных сессий «ввёл и ушёл, не долистав до результата» (смотреть Вебвизор).

## Ограничения

- Визуальный стиль не меняем (цвета, шрифты, карточки, логотип) — только структура и поведение на узких экранах.
- Сайт статический (`backend/public`, ServeStatic). EN — исходник; RU/RO + SEO-блок генерит `npm run build:landing`
  из `landing/i18n.json`; устаревание ловит `scripts/landing-i18n.test.js`. Все новые строки — с `data-i18n`.
- Десктоп и поисковики видят то же, что сейчас (кнопки Add to Chrome в HTML остаются).
- ToS: в новых текстах DAT не упоминаем, авто-пилот не рекламируем.
- Подход A: доработка текущих страниц. Отдельные `/m/`-страницы и переход на генератор сайтов отклонены.

## Часть 1. HOS-калькулятор

### 1.1 Плашка результата
- Только `max-width: 860px`. Закреплена внизу экрана: главный ответ (`js.now` — «You can drive 8h 0m right now,
  then …») и цвет самого тесного лимита (зелёный/янтарный/красный — те же классы, что у полос «Time left»).
- Тап → `scrollIntoView` к блоку «Time left». Когда блок «Time left» виден (`IntersectionObserver`), плашка скрыта.
- Источник данных — тот же результат, что считает `update()` в `hos-page.js`; новой математики нет. Текст и цвет
  плашки — чистая функция `summaryFor(result)` (тестируется отдельно).
- Плашка не перекрывает баннер cookies: пока баннер показан, плашка над ним.

### 1.2 Ввод
- Поля ч/м и `inputmode="numeric"` без изменений.
- Запоминание ввода: на каждый `update()` состояние формы → `localStorage['ll_hos_form']` (JSON, версия схемы `v:1`);
  при загрузке — восстановление до первого `update()`. Ссылка «Reset» очищает ключ и форму. Все обращения к
  хранилищу в try/catch: недоступно → поведение как сейчас. Чистые `serializeForm/restoreForm`.
- ~~`<details>` для «Split sleeper» и «recap»~~ — снято при планировании (08.10): эти блоки уже свёрнуты
  своими галками (`#split`, `#byday`), поля видны только при включённой галке; `<details>` ничего не сокращает.

### 1.3 Офлайн и иконка на экране
- `backend/public/sw.js` (scope `/`): precache `/hos-calculator/`, `/ru/hos-calculator/`, `/ro/hos-calculator/`,
  `/js/hos-trip.js`, `/js/hos-page.js`, `/js/site.js`, `/css/site.css`, иконки. Fetch: навигация на пути
  калькулятора → network-first с фолбэком в кэш; ассеты из precache → stale-while-revalidate; **всё остальное
  (лендинг, API, Метрика) — не перехватывается**. Версия кэша = константа в sw.js, старые кэши чистятся в `activate`.
- Регистрация SW — только со страниц калькулятора.
- Манифест на язык: `/hos-calculator/manifest.webmanifest` (+ `/ru/…`, `/ro/…`), `name` локализован,
  `start_url` = страница своего языка, `display: standalone`, иконки 192/512 (из текущего `icon.png`).
  RU/RO-манифесты генерит `build:landing`.
- Кнопка «Add to Home Screen»: Android/Chrome — по `beforeinstallprompt` (отложенный prompt). iOS (нет события) —
  после первого успешного расчёта однократная подсказка «Share → Add to Home Screen» с крестиком; флаг показа в
  `localStorage`. Цель Метрики `a2hs`.

### 1.4 Блок про расширение под результатом
На десктопе — как сейчас. На телефоне вместо «Add to Chrome» — кнопки из части 2.

## Часть 2. Лендинг и общие элементы

### 2.1 Определение телефона
Inline-скрипт в `<head>` всех публичных страниц (до отрисовки): `/Android|iPhone|iPad|iPod/` в UA или
`/Macintosh/` + `navigator.maxTouchPoints > 1` (iPadOS) → класс `is-mobile` на `<html>`. CSS: `.is-mobile .cta-desktop
{display:none}`, `.cta-mobile` видна только при `.is-mobile`. Без JS — десктопный вариант.

### 2.2 Мобильные кнопки (везде, где сейчас Add to Chrome)
- **«Send me the link»** (основная): `navigator.share({title, text, url})`, url = лендинг языка страницы
  `?utm_source=share`. Нет `navigator.share` или ошибка, кроме отмены пользователем → `mailto:?subject=…&body=…`
  (без адресата; тело — ссылка + «Open on your computer in Chrome»). Цель `share_link`.
- **«Get it in Telegram»** (вторая): ссылка на `/api/v1/telegram/install?lang=<lang>` — бэкенд отвечает 302 на
  `https://t.me/<TELEGRAM_BOT_USERNAME>?start=install_<lang>` (имя бота из env, на сайте его нет; без env → 302 на
  лендинг). Цель `tg_install`.
- Под кнопками строка: «LoadLens is a Chrome extension for your laptop or desktop.»
- В hero дополнительно текстовая ссылка «Try the free HOS calculator →» (видна только на телефоне).

### 2.3 Баннер cookies
На телефоне — узкая полоса внизу: одна строка («Analytics cookies.» + «Details») и Decline/Accept в строке,
высота ≤ 80px. Десктопный вид и логика согласия (`ll_consent`, Метрика только после Accept) без изменений.

### 2.4 Остальные страницы
`terms`, `refund`, `privacy`, `stats` (+ RU/RO-лендинги) — проверка на 390px: нет горизонтального скролла,
таблицы `stats` — в контейнере с `overflow-x:auto`, длинные `code` переносятся. Точечные правки CSS.

## Часть 3. Бот: `/start install`

### 3.1 Разбор
Чистая `parseInstallStart(text): 'en'|'ru'|'ro'|null` в `telegram.service.ts`: `/start install`, `/start install_en|ru|ro`
(+ `@bot`-суффикс). `parseStartCommand` (токен привязки, 8–64 символа) не меняется; в `handleWebhook` —
отдельная ветка до неё.

### 3.2 Ответ
На языке команды: ссылка на Chrome Web Store `?utm_source=telegram`, «Open it in Chrome on your laptop or desktop»,
«I'll remind you once tomorrow». Повторный `/start install` — ссылка снова, напоминание не сбрасывается.

### 3.3 Хранение
Модель `install_leads`: `chat_id` (PK, string), `lang`, `created_at`, `reminded_at` (nullable). Таблица новая —
создаётся `synchronize`. Только id чата и язык. `privacy.html` (только EN — страница одноязычная): строка — храним id чата и язык, чтобы
прислать одно напоминание, удаляем через 30 дней.

### 3.4 Напоминание
`InstallLeadsService` в `TelegramModule`, `@Cron('0 * * * *')` (как `trial-notices`):
- выборка: `reminded_at IS NULL`, `created_at` между now−7д и now−24ч, `chat_id` нет в `users.telegram_chat_id`;
- шлём «Did you get LoadLens on your computer?» + ссылку; `reminded_at = now` **независимо от успеха отправки**
  (заблокировавший бота не опрашивается каждый час);
- в том же тике удаление записей старше 30 дней.
Без `TELEGRAM_BOT_TOKEN` — ни ответа, ни напоминаний (как остальной Telegram).

  работает; Desktop Chrome — всё как раньше; `scrollWidth == innerWidth` на всех публичных страницах.
