## Daily Report — 2026-09-16

**Project:** LoadLens
**Author:** Bogdan Bucataru

1. Fixed a defect that locked free users out of their own accounts permanently, because the password reset code could only be delivered through a channel they were not allowed to connect.
2. Opened that channel to every account while keeping the paid alerts behind the subscription, so account recovery works for everyone without giving away what customers pay for.
3. Replaced the dead-end upgrade notice with an honest description of what the paid plan actually adds, so free users see the value instead of a locked door.
4. Started showing how long ago each load was posted, which after the rate is the fact that decides whether a call is worth making, since an old posting is usually already taken or is bait.
5. Marked postings under half an hour old as fresh and those older than six hours as stale, so a dispatcher can judge a load at a glance without reading numbers.
6. Reordered the panel and the alert messages so the newest postings come first, and made the limit on a batch of alerts drop stale loads rather than fresh ones.
7. Added the posting age to the alert messages and to the exported spreadsheet, so the information travels with the load wherever the customer works with it.
8. Added a rule setting that keeps loads older than a chosen number of minutes out of alerts entirely, which is what stops recycled postings from filling a customer's phone.
9. Covered all of the new behaviour with automated tests and confirmed the settings screen works correctly in a real browser before release.
10. Released a new version of the extension containing this work together with everything from the previous build, ready for submission to the Chrome Web Store.
