# Дизайн: радиус соседних рынков + живая свежесть цепочек

**Дата:** 2026-06-17
**Проект:** LoadLens
**Статус:** утверждён к реализации

## Проблема

Диспетчер держит панель открытой и **мониторит рынок вживую**, ожидая непрерывных цепочек
грузов с минимальным deadhead. Два разрыва мешают:

1. **Свежесть.** Цепочка строится на грузе, который уже забукан/снят. Окно крауд-пула — 72ч,
   и груз, виденный 70ч назад, ранжируется наравне со свежим. Водитель приезжает в рынок, а
   плеча уже нет.
2. **Непрерывность.** Планировщик матчит onward-плечи по точному ключу рынка (`CITY_ST`).
   Если в рынке назначения нет свежих грузов, цепочка обрывается на одном плече — даже если в
   городе в 40 милях груз есть.

Крауд-пул из 30+ брокеров (каждый с плагином, льющим перехваченные грузы в `POST /loads`) — уже
существующий фундамент. Задача не в транспорте ingest, а в **качестве использования этого пула**.

## Решения (зафиксированы в брейншторме)

- **Ядро итерации — радиус соседних рынков.** Onward-плечи берём не только из точного рынка, но
  из рынков в радиусе deadhead. Прямо отвечает на «минимальный deadhead»: небольшой крюк ради
  живого продолжения цепочки.
- **Свежесть = recency-decay (1) + кросс-брокерный инференс по каденсу пере-наблюдения (2).**
  Без правок `inject.js` — чисто серверная механика поверх `lastSeen` и счётчика наблюдений.
  Явные события исчезновения (диф снимков в `inject.js`) — отложены.
- **Транспорт живости — delta-poll**, не SSE. Инфра Cloudflare-proxied + Coolify, где SSE
  капризен с буферизацией; poll с `since` каждые 5–10 c операционно тривиален и для живого
  монитора неотличим. SSE — возможная оптимизация позже, дельта-эндпоинт переиспользуется.
- **Координаты — только seed-рынки** (~40+ в `markets.seed.json`). Рынки без координат
  деградируют к строгому матчу. Газеттир US-городов (`CITY_ST → lat/lng`) — отдельный data-asset,
  отложен.

## Архитектура

Граница врезки в существующий код:
- `content.js:fetchCrowdLoads(markets)` уже тянет onward-рынки в `crowdCache: market -> CrowdLoad[]`.
- `content.js:chainPool(visible)` сливает видимые + крауд-грузы в плоский пул (дедуп по `loadId`).
- `planner.js:plan()` индексирует пул по точному `originMarket` (`byOrigin`), HOS-гейт + beam search.
- `geo.service` уже умеет haversine (`haversineMiles` экспортируется) + OSRM + кэш `lane_distances`.

### 1. Backend — гео и радиус

**`nearbyMarkets(market, radiusMi = 75) -> [{ market, crowMi }]`**
Чистая функция. Haversine по seed-координатам (`markets.seed.json`), возвращает seed-рынки в
радиусе, включая сам рынок (`crowMi = 0`). Рынок без координат → массив из самого себя
(деградация к строгому матчу). Результат отсортирован по `crowMi`, ограничен сверху
(`MAX_NEIGHBORS`, напр. 12) чтобы не раздувать запросы.

**`GET /loads/near?market=&radiusMi=&equipment=&since=`**
Отдаёт живые грузы из рынка **и соседей** одним ответом.
- `radiusMi` — дефолт 75, clamp `[0, 200]`.
- Запрос: `originMarket IN (nearbyMarkets)` + окно свежести (`lastSeen > now - 72h`).
- Каждый груз аннотирован:
  - `originDeadheadMi` — крюк рынка-соседа от запрошенного `market` (= `crowMi` соседа).
  - `liveness` — серверный скор свежести (см. §2).
  - `likelyGone` — флаг «вероятно ушёл» (см. §2); из основного списка исключаются (или флагуются
    так, чтобы планировщик их отбросил).
- Старый `GET /loads?origin=` **остаётся** для fallback / построчных бейджей.

### 2. Backend — свежесть (1 + 2, без `inject.js`)

- Новая колонка **`seen_count INTEGER`** в `loads` — идемпотентный
  `ALTER TABLE loads ADD COLUMN IF NOT EXISTS seen_count INTEGER DEFAULT 1` в `main.ts`
  (synchronize не меняет существующие таблицы).
- При upsert в `ingest`: инкремент `seen_count` для повторно виденных грузов (через
  `sequelize.literal('seen_count + 1')` в `updateOnDuplicate` либо явный путь).
- Скор `liveness` (серверный, 0..1):
  - **recency-decay** — функция от `now - lastSeen` (напр. линейный/экспоненциальный спад до конца окна).
  - **каденс пере-наблюдения** — для часто виденных (`seenCount >= MIN_OBS`, напр. 4)
    `cadence = (lastSeen - firstSeen) / (seenCount - 1)`; если `now - lastSeen > GONE_FACTOR * cadence`
    (напр. `GONE_FACTOR = 4`) → `likelyGone = true`.
  - **тонкие lane** (`seenCount < MIN_OBS`) → только decay, `likelyGone` **не** ставим (гасим
    ложные срабатывания при малом числе наблюдателей).

### 3. Backend — delta-poll

- С параметром `since` (серверный `ts` из прошлого ответа — **не** клиентские часы):
  `/loads/near` отдаёт `{ added: [...], updated: [...], gone: [loadId], ts }`.
  - `added` / `updated` — грузы с `lastSeen > since`.
  - `gone` — `loadId`, ставшие `likelyGone` (или выпавшие из окна) после `since`.
  - `ts` — серверное время ответа, клиент эхо-передаёт его в следующий poll.
- Без `since` — полный снимок neighborhood (первый вызов при открытии панели).

### 4. Planner (`shared/planner.js`)

- Новая инъекция **`nearby(market) -> [{ market, miles }]`** в `opts`. По умолчанию отсутствует →
  текущее поведение строгого матча сохраняется, существующие тесты не ломаются.
- В каждом узле beam search кандидаты = грузы из `p.node` **∪** из соседей `nearby(p.node)`.
  Deadhead по-прежнему через существующий `distance(p.node, load.originMarket)` (соседский крюк
  он уже учитывает); HOS-гейт (`stepHos`) не трогаем.
- «Минимальный deadhead» обеспечивается самим objective: лишние мили крюка раздувают `totalMiles`
  и топливо/тарифы → крюковые цепочки ранжируются ниже бескрюковых **автоматически**, без
  отдельного штрафа.

### 5. Extension

- **`api.js`**: `getLoadsNear(market, { equipment, since })` → `GET /loads/near`.
- **`content.js`**:
  - `fetchCrowdLoads` зовёт `/loads/near` (в `crowdCache` ложится neighborhood, а не один рынок).
  - При открытой панели — poll-цикл (5–10 c) с `since` по рынкам текущей цепочки → мерж дельты
    (`added` / `updated` upsert в пул, `gone` удаляет) → пересчёт `LLPLAN.plan` → ререндер.
  - Цикл **стоп** при закрытии панели и на `visibilitychange` (скрытая вкладка не поллит).
- Планировщику передаём `nearby`, считаемый **локально** по vendored `LLSEED`
  (`markets.seed.json` → `vendor/`), тем же радиусом, что и бэк.

## Обработка ошибок и границы

- distance-фейл → haversine ×1.2 (уже реализовано в `geo.service`).
- Рынок без seed-координат → `nearbyMarkets` возвращает только сам рынок (строгий матч).
- Clock-skew → используем **только серверный `ts`**, клиент его не генерирует.
- Bound: `MAX_NEIGHBORS` на рынок; ограничение числа рынков подписки (цепочка ≤ 3 плеч →
  ≤ 3–4 onward-рынка × соседи); существующий лимит 25 запросов в `fetchCrowdLoads` сохраняем.
- Poll не идёт при скрытой вкладке / закрытой панели — нагрузка ограничена активными мониторами.

## Тестирование

- **planner** (zero-dep, `shared`):
  - синтетический `nearby` → цепочка продолжается через соседа в 60 миль, когда точный рынок пуст;
  - deadhead соседского плеча прибавлен к `totalMiles`;
  - крюковая цепочка ранжируется **ниже** бескрюковой при прочих равных;
  - без `nearby` поведение идентично текущему (регрессия).
- **backend** (jest):
  - `nearbyMarkets` — радиус-математика (попадание/непопадание, сортировка по `crowMi`, рынок без координат);
  - `/loads/near` — соседи в ответе + корректный `originDeadheadMi`;
  - свежесть — `seen_count` инкрементится при пере-ingest; `likelyGone` ставится только при `seenCount >= MIN_OBS`;
  - delta — `since` отдаёт только изменённое + `gone`.

## Вне scope этой итерации

- Явные события исчезновения через диф снимков в `inject.js`.
- SSE/WebSocket транспорт (текущая итерация — delta-poll).
- Газеттир US-городов для координат не-seed рынков.
- Прогнозные плечи (forecast) как заглушка при пустом neighborhood — уже частично есть, не трогаем.
