# Дизайн: UI смены пароля в попапе

Date: 2026-06-27
Status: approved

## Цель

Дать залогиненному пользователю сменить пароль из попапа расширения. Эндпоинт
`PATCH /api/v1/users/me/password` уже реализован и в проде — нужен только UI-слой.
Поверхность: **только попап** (там живут все залогиненные юзеры, включая аккаунт админа).

## 1. `extension/api.js` — метод в `LLAPI`

```js
async function changePassword(currentPassword, newPassword) {
  const res = await authedFetch("/users/me/password", {
    method: "PATCH",
    body: JSON.stringify({ currentPassword, newPassword }),
  });
  if (!res || !res.ok) {
    const msg = res ? ((await res.json().catch(() => ({}))).message || `ошибка ${res.status}`) : "нужен вход в аккаунт";
    throw new Error(Array.isArray(msg) ? msg.join(", ") : msg);
  }
  return { ok: true };
}
```
Добавить `changePassword` в возвращаемый объект `LLAPI` (строка ~268).
`authedFetch` уже даёт авто-рефреш на 401 (как у `deleteAccount`).

## 2. `extension/popup.js` — форма в секции аккаунта

В `accRow(user)` (залогиненное состояние) добавить кнопку **«Сменить пароль»** рядом с
«Выйти»/«Удалить аккаунт». Клик — toggle инлайн-формы внутри `.acc`:
- два поля: `acc-cur` (текущий пароль), `acc-new` (новый, placeholder «мин. 8»), оба `type=password`;
- кнопка **«Сохранить»** (`acc-pwd-save`);
- строка результата (`.err`): успех → «Пароль изменён», поля очищаются, форма сворачивается;
  ошибка → сообщение от сервера (неверный текущий / новый = старый) или клиентское «минимум 8 символов».
- Клиентская проверка перед отправкой: оба поля ≥ 8 символов; иначе показать «минимум 8 символов»
  без запроса. Остальное валидирует сервер (400).

Реализация — отдельная функция `pwdForm(container)` рядом с `accRow`, чтобы `accRow` остался
тонким. Сабмит: `await LLAPI.changePassword(cur, neu)` → успех/ошибка в `.err`.

## 3. `extension/styles.css`

Переиспользовать существующие `.acc`, `.err`, `.note`, `.btns`. Добавить по минимуму, только
если инлайн-форме не хватит текущих классов (напр. отступ для скрытого блока).

## Тестирование

`api.js`/`popup.js` — I/O-glue; в этом репозитории НЕ покрываются юнит-тестами (как `login`,
`deleteAccount` — их тоже нет в наборе `node --test`). Следуя конвенции кодовой базы:
- **Ручная проверка** на загруженном распакованном расширении: войти → «Сменить пароль» →
  неверный текущий (видим ошибку) → корректная смена (видим «Пароль изменён») → перелогин новым.
- Бэкенд-эндпоинт уже покрыт юнит-тестами (`users.service.spec.ts`, 4/4) и проверен на проде round-trip.

## Границы (YAGNI)

- Только попап; `admin.html` и сам эндпоинт не трогаем.
- Без «показать пароль», без индикатора силы пароля, без подтверждения нового пароля вторым полем.
